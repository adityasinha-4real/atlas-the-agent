# Milestone M6 — Hardening

**Status:** ✅ complete (v0.6.0). Robustness only — **no new agent capabilities**.
Every M6 subsystem is off, passive, or a no-op by default, so a default install is
**byte-for-byte M5** (invariant **I-23**, enforced by a parity test).

**Demo:** enable observability (`ATLAS_METRICS_ENABLED=true`), run a goal, and
scrape `GET /metrics` (Prometheus text) and `GET /ready` (dependency probe) — the
run itself is unchanged. Kill the process mid-run and restart: the startup
**reconciler** brings the interrupted run to a consistent terminal state with an
attributed recovery event (no orphaned `RUNNING` rows). `make bench` prints
latency/RSS baselines; `make evals` regenerates the golden `scorecard.md`.

Full design: [RFC-0004](../rfc/0004-m6-hardening.md); decisions
[ADR-0020](../adr/0020-deterministic-benchmark-harness.md)…[0024](../adr/0024-single-writer-concurrency-model.md).

## 1. Scope shift from the original sketch

The M1 roadmap sketched M6 as crash-**resume**, a `code_sandbox` tool, and a
`PAUSED` state. RFC-0004 **re-scoped M6 to hardening-only**: those are agent
capabilities, and v0.5.0 froze the capability surface. Instead M6 makes the
existing runtime **measured, observable, recoverable, and audited**. Recovery is
**reconcile-to-terminal, not resume** ([ADR-0021](../adr/0021-crash-recovery-reconcile-not-resume.md));
the History/replay page moved to M7.

## 2. What shipped (by phase)

1. **Measurement foundation** — a deterministic benchmark suite (`bench/`:
   latency, RSS, `EXPLAIN QUERY PLAN`, FTS, event-stream) with committed baselines
   and a CI threshold guard, plus **passive observability** (`atlas/obs/`: metrics
   registry, `/metrics`, `/ready`, opt-in JSON logging).
2. **Storage & runtime optimization** — benchmark-justified only: an
   `ix_runs_created` index (list pagination → index scan, ~60 % faster p50/p95) and
   `PRAGMA temp_store=MEMORY`, each with a recorded before/after delta and no
   observable behavior change.
3. **Recovery, integrity & replay** — the startup **reconciler**, the canonical
   **`fold_events`** reducer + golden-ledger fixtures, `sequence_is_intact` ordering
   check, optional `PRAGMA quick_check`/FTS-drift integrity, a `schema_meta` version
   row, and a repeated-run determinism test.
4. **Evaluation harness** — `evals/`: 8 goldens (single/multi-task, tool-use,
   retry, replan, partial, failure, memory-lift) driven through the real runtime on
   a scripted gateway → committed `scorecard.md` + `results.json`. Lands the
   M5-deferred item.
5. **Audits, CI & release** — API/security/config/tech-debt/doc audits with
   checked-in reports; `.github/workflows/ci.yml` (Windows + Linux matrix, coverage
   floor, bench-ci, evals, doc-lint); version → **0.6.0**; this doc + CHANGELOG +
   README/ARCHITECTURE/TODO.

## 3. New invariants (I-23…I-28)

| # | Invariant |
|---|---|
| I-23 | Hardening is behavior-preserving at defaults (byte-for-byte M5). |
| I-24 | The ledger is authoritative; replay via `fold_events` is deterministic. |
| I-25 | Observability is passive — recording can never raise into a run. |
| I-26 | Recovery is ledger-derived and idempotent. |
| I-27 | Migrations are additive and downgrade-safe. |
| I-28 | Resources are bounded / label cardinality is fixed. |

## 5. Acceptance tests (deterministic)

- **Parity** — metrics on vs off produce identical normalized event streams
  (`test_obs_metrics`); M1–M5 suites remain green under defaults.
- **Recovery** — interrupted runs reconcile to a terminal state, idempotent
  re-reconcile, no data loss (`test_recovery`).
- **Replay/determinism** — golden-ledger round-trip + equivalence, reordering
  detection, repeated-run event equality (`test_replay`, `test_determinism`).
- **Integrity/migration** — `quick_check`/FTS-drift, additive `schema_meta`/index on
  a v0.5.0-shaped DB (`test_integrity`, `test_storage_optimization`).
- **Evals** — 8/8 goldens pass; memory-lift recall; the step metric is meaningful
  (`test_evals`).
- **Doc-lint** — version + config parity across the repo (`test_docs_parity`).
- **307 tests total**, ruff clean, coverage 92 % (floor 85 %), frontend build green.

## 6. Release & migration notes

- **Versions** → **0.6.0** (backend `__version__` + `pyproject.toml`, frontend
  `package.json`, `GET /health`), asserted in lockstep by `test_docs_parity.py`.
- **Migration** — additive/idempotent (I-27): first start on a v0.5.0 DB creates the
  `schema_meta` row + `ix_runs_created` index; no manual step, no data loss,
  downgrade-safe. Alembic still deferred until Postgres.
- **Recovery default** — `ATLAS_RECOVERY_ENABLED` defaults **on** but is
  behavior-preserving for cleanly-terminated runs (only interrupted runs change).

## 7. Not in scope (deferred to M7+)

History/replay page; OpenAPI-generated TS client; recall at execution/reflection
time; semantic/FAISS memory; `ruff` `S` (bandit) rules; multi-user auth. All are
additive follow-ups behind existing seams.
