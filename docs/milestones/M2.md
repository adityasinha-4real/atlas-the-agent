# Milestone M2 — Tool-using agent (single task)

**Status:** ✅ complete (v0.2.0)

**Demo:** a goal such as _"What is 15% of France's population?"_ drives a live
event stream — `thought → tool.call → tool.result → …→ answer` — as the agent
reasons, calls tools, and finishes. The run is persisted and replayable exactly
like M1.

> With the `echo` provider (no Ollama) the agent gracefully answers directly —
> the tool loop is exercised deterministically by the FakeLLM tests. With Ollama
> (`qwen2.5:7b-instruct`) the full think→search→calculate→answer loop runs live.

## 1. Objectives

1. A `Tool` ABC + `ToolResult` + a registry that **traps every failure into an
   observation** — no tool exception crosses the executor loop (design §1.2c, §1.6).
2. The four P0 tools (design §5): `calculator`, `file_read`/`file_write` (path
   jail), `web_search` (ddgs), `web_fetch` (HTML→text, summarize-at-source).
3. A flat JSON **action envelope** (`tool_call | finish`) with tolerant parsing
   and a bounded **repair loop** (design §1.2b, §3).
4. The **Executor ReAct loop** (≤5 iterations): think → tool → observe → …→ finish.
5. A scripted **FakeLLM** so the whole loop is testable with no model/network
   (design §10.5).
6. Event-feed UI that renders thoughts, tool calls, and tool results.

## 4. Design decisions

- **Envelope is flat**, not a discriminated union — flat JSON is markedly more
  reliable for 7B models (design §1.1). Validation enforces `tool` on
  `tool_call` and `answer` on `finish`.
- **Registry is the safety boundary.** Tools raise `ToolError` for expected
  failures; `ToolRegistry.execute` validates args, applies a timeout, and
  converts unknown-tool / bad-args / timeout / crash into a failed `ToolResult`.
- **Graceful degradation** (ADR-0008): if the model never emits a valid envelope
  for a turn (after repair), its *first* response is accepted as the answer
  rather than crashing the run. Keeps the `echo` dev path usable and bounds
  worst-case behavior; reflection (M4) will later judge such answers.
- **Manager vs executor split:** the executor owns reasoning/tool events; the
  manager owns run lifecycle and streams the final answer as `answer.token`
  events (UI continuity with M1).

## 5. Acceptance tests (`make test-m2`)

- `test_tools.py` — calculator (safe eval, rejects unsafe/invalid), file
  read/write roundtrip + **path-jail escape denied**, registry unknown-tool /
  bad-args / **timeout** / crash all become observations.
- `test_envelope.py` — parses plain / fenced / prose-wrapped JSON, braces inside
  strings, and rejects malformed / mis-shaped envelopes.
- `test_executor.py` — tool_call→finish, tool-result observations, repair
  recovery, degradation to first answer, iteration-budget exhaustion, cooperative
  cancel, bad tool args surfaced (not crashed).
- `test_runtime_m2.py` — full demo flow through `RunManager` with the FakeLLM:
  ordered `thought→tool.call→tool.result→answer.completed→run.completed`, DONE.
- M1 REST/WS tests remain green (60 tests total).

## 6. Not in scope (later milestones)

verified by unit tests for arg-validation and graceful failure, not live calls.
