# Milestone M5 — Episodic memory

**Status:** ✅ memory complete (v0.5.0). Deferred within M5: eval harness +
History/replay page (see [TODO](../TODO.md)).

**Demo:** enable memory, run a goal (e.g. *"convert the height of Everest in meters
to feet"*), then run a **related** goal (*"convert the depth of the Mariana Trench
in meters to feet"*) — the second run shows **"◆ recalled 1 lesson from past runs,"**
injects it into the planner, and produces a tighter plan. The **Memory** page lists,
searches, pins, and forgets what the agent has learned. Persisted and replayable
exactly like M1–M4.

> Memory is **opt-in**: `ATLAS_MEMORY_ENABLED` defaults to **off**, in which case
> behavior is byte-for-byte M4 (invariant I-15). It is also **best-effort** — no
> recall/write/distillation failure can affect a run (I-14). Both are exercised
> deterministically by the FakeLLM (`ScriptedGateway`) tests.

Full design: [RFC-0003](../rfc/0003-m5-episodic-memory.md); decisions
[ADR-0016](../adr/0016-episodic-memory-record.md)…[0019](../adr/0019-memory-best-effort-optional.md)
(building on [ADR-0004](../adr/0004-fts5-over-faiss.md)).

## 1. What shipped

1. **`MemoryStore` seam + `EpisodicStore`** (SQLite FTS5) — the single boundary all
   memory reads/writes cross; a semantic/FAISS tier is a drop-in (I-21).
2. **`memories` table + `memories_fts`** FTS5 index and triggers via an idempotent
   migration with a `LIKE` fallback (ADR-0017); `run_id` is `ON DELETE SET NULL`.
3. **Recall pipeline** — at plan time, ranked/gated/budgeted lessons are injected
   into the planner as untrusted hints; replans reuse them (ADR-0018).
4. **Write pipeline** — best-effort distillation (LLM + heuristic fallback), written
   once per run (idempotent) after the answer, on `done`/`partial` only; then prune
   (ADR-0016, ADR-0019).
5. **Events** — `memory.recalled` (carrying the exact injected text, I-19) and
   `memory.written`.
6. **API** — `GET /memories` (+ `?q=` search + pagination), `GET /memories/{id}`,
   `DELETE /memories/{id}`, `POST /memories/{id}/pin` · `/unpin`.
7. **Frontend** — a **Memory** page (search/paginate/inspect/pin/forget); the Run
   page renders recalled lessons + a "saved to memory" note; the feed renders the
   new events.

## 2. Control flow

```
PLANNING:
  if memory_enabled:
    recall(goal) → FTS5 candidates → rank (relevance+salience+recency+outcome)
                 → min-score gate → top-k → char budget → dedupe
    if lessons: emit memory.recalled{rendered} ; touch salience
  Planner.plan(goal, lessons)                 # lessons=None ⇒ identical to M4
RUNNING … (M4 loop unchanged; a replan reuses the same lessons) …
SYNTHESIS → DONE / FAILED(+partial)
finalize (after answer delivered, best-effort):
  distill(run) → MemoryStore.write (upsert per run) → prune → emit memory.written
```

Precedence of guarantees: **disabled = M4 (I-15) > best-effort isolation (I-14)**.
No write call-site exists on budget-exhaustion or cancellation.

## 4. Acceptance tests (deterministic)

- `test_memory_store.py` — FTS search/exclusion, LIKE fallback, upsert-per-run,
  run-deletion survival (SET NULL), touch/salience, prune + pinned exemption +
  expiry, migration on a v0.4.0-shaped DB, serialization.
- `test_memory_ranking.py` — relevance ordering (absolute), pinned precedence,
  recency tie-break, k/char-budget/min-score gates, redundancy skip.
- `test_memory_runtime.py` — write on done/partial, LLM + heuristic distillation,
  min-tasks skip, recall injection + event fidelity, empty recall, **cross-run
  learning**, replan reuse, **disabled = M4 parity**, recall/write **failure
  isolation**.
- `test_api_memory.py` — list/search/paginate/get/delete/pin/unpin + disabled-empty.
- M1–M4 tests remain green (**243 tests total**).

## 5. Release, demo & migration notes

- **Versions** → **0.5.0** (backend `__version__` + `pyproject.toml`, frontend
  `package.json`, surfaced at `GET /health`).
- **Demo:** set `ATLAS_MEMORY_ENABLED=true` (`.env`), start backend + frontend, run
  two related goals; watch the recall banner and the Memory page. With the `echo`
  provider the heuristic writer is used (no model needed for the write).
- **Migration:** additive and idempotent — first start on a v0.4.0 DB creates
  `memories` + the FTS index/triggers; **no manual step, no data loss, no existing
  table altered**. Full Alembic remains deferred until Postgres.

## 6. Not in scope (deferred)

Within M5: the **eval harness** (goldens → `scorecard.md`) and the **History page +
run replay**. Beyond: recall at execution/reflection time, semantic/FAISS memory,
cross-instance memory (all natural, additive follow-ups). Next milestone: **M6 —
hardening** (crash-resume, `code_sandbox`, `PAUSED`).
